# Local terminal — SST-029

**Status: automated gates DONE — 2026-10-19.** Independent TEST/REVIEW/DELIVER complete. [ADR 0005](adr/0005-local-terminal-platforms.md), [execution plan](agent-runs/implementation-plan.md#sst-029-execution-plan--macos-local-pty--platform-declarations-2026-10-18).

The explicit **New local terminal** action opens a new shell on **LOCAL · This Mac**. It runs an interactive `/bin/zsh` child in the user's home directory with the user's OS privileges. A fixed main-owned `/bin/sh` guardian remains the PTY session leader until cleanup completes; its script invokes the selected shell through positional arguments and never interpolates user input. Opening the app, restoring layout or selecting a page does not open or replay a local shell. Split starts another shell; reconnect/restart starts a fresh process and generation. Previous commands and queued input are never replayed.

Local terminal targets have no saved-host reference or SSH endpoint. There is no SSH trust/authentication prompt and no local SFTP, tunnel or remote-edit capability. Local and remote tabs remain distinct from their Ready/closed operational state. Saved workspace templates and multi-target tools accept saved SSH targets only and state that restriction. Active-session snippets can prepare and run text on a captured local generation; Paste and Run remain distinct and sending bytes does not prove command success.

## Boundaries and data

The only local-start payload is the validated current `{ owner }`. Main chooses shell, arguments, cwd and environment. The renderer cannot provide launch configuration, arguments, environment, cwd or PID. The fixed main-authored shell path is display metadata; no native object or process-control handle crosses IPC. All ordinary terminal writes still require the exact owner/session/generation, and a renderer's stream has one consumer and ordered sequence numbers. App lock gates privileged IPC. Lock, suspend, window revocation and quit fence input and begin native disposal; resuming never automatically starts a shell.

The environment is an explicit allowlist, not a copy of the application's process environment. Application OAuth/build credentials, test namespace/profile flags, Node/Electron injection/debugger flags and dynamic-loader overrides are excluded. Shell startup files can change the environment, execute programs and write normal shell history independently; ssterm does not read or retain that history. Terminal output is process memory only under the existing terminal policy. The guardian writes only the interactive child's numeric wait status into a `0600` file inside a private transient `0700` directory under the OS temporary directory (`ssterm-local-session-*`); no commands, output or credentials are written there. Confirmed disposal removes it. A forced OS/app termination can leave numeric status metadata behind. Child status uses shell wait conventions (a signal can produce `128 + signal`); it is not interpreted as proof that an explicit `exit 130` was a signal. Schema stays 4.

node-pty 1.1.0 is main-only and pinned. Its macOS N-API binary and spawn helper ship with the application. `npm ci --ignore-scripts` is followed by `npm run runtime:prepare` to set the shipped helper's execute mode. Other platforms/architectures display an explicit unsupported state; a missing/broken native runtime fails only the local feature with an app-authored error. See the [platform capability matrix](adr/0005-local-terminal-platforms.md#platform-matrix).

## Native IO and cleanup

The adapter admits at most 32 native sessions independently of registry history. A cleanup whose process death cannot be confirmed retains its admission permit after finite attempts; the registry reports its bounded cleanup timeout and the slot is unavailable for the rest of that app process. Avoidable descriptor/status-file resources are released best-effort without pretending process cleanup succeeded.

Input is admitted whole under a 512 KiB queue, including one maximum paste; a busy refusal does not send a prefix. Output uses raw bytes, a 256 KiB renderer credit window and a 1 MiB adapter buffer limit. A duplicated owned input descriptor isolates bounded writes from node-pty's hidden queue and descriptor reuse. A pinned Unix ReadStream seam prevents the upstream 200 ms exit timer from silently discarding a deliberately paused tail; the real delayed-open regression exceeds that timer. Native/version-specific seams are isolated in the adapter and require real fixtures, including paused-consumer exit tails. Resize and Ctrl+C go through the PTY; no shell command is used to implement them.

Closing a pane stops its guardian, interactive shell and owned foreground/background descendants with confined process metadata and bounded escalation. Disposal is idempotent and reports actual native drain. This does not sandbox arbitrary local commands or guarantee cleanup of deliberately detached/reparented daemons, external editor/shell copies, host crash or an OS-forced application kill. Files and external effects created by user commands are not rolled back. Close/quit prompts explicitly identify local targets and the termination of local jobs.
