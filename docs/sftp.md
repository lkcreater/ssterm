## Session kind

An SFTP browser is a session of kind `sftp` in the same registry as terminals, with its own SSH connection. It therefore shares the known-host policy, credential prompts, keepalive, lock and quit handling, owner revocation, the 32-session cap and generation fencing. `connect(owner, hostId, kind)` starts it, reconnect keeps the kind, and `registry.sftp(owner, id, generation)` is the same exact fence that `terminal()` uses, so a stale or foreign request never reaches a channel. The adapter opens the `sftp` subsystem instead of a shell: a refused subsystem is `subsystem-unavailable`, a refused channel `channel-open-failed`, and Ready means the subsystem negotiated and the home directory resolved. Closing an SFTP session never affects terminals on the same host, and a terminal exit or reconnect never affects SFTP. The terminal controller ignores SFTP sessions.

A single shared connection for terminal, SFTP and tunnels (one authentication per host) is the recorded upgrade path; a channel on the terminal connection was rejected because it would die with the terminal, hold registry resources until teardown and leak channel slots when the subsystem is refused.

## Capability

`SftpSession` offers `home`, the negotiated `maxRead` and `maxWrite` (server limits, reads capped at 261,120 bytes below ssh2's 256 KiB packet limit; servers without the limits extension allow about 32 KiB), `realpath`, `stat`, `lstat`, `list`, `openRead` and `openWrite` (exclusive create only). Paths are absolute lexical POSIX paths of at most 4,096 UTF-8 bytes without NUL. Listings are capped at 10,000 entries with `truncated` and `skipped` counts; names containing `/`, NUL, empty names or names over 1,024 bytes are skipped, and names that do not decode as UTF-8 are marked unaddressable. Server status codes map to fixed app codes (not found, permission denied, failure, invalid path, unsupported, connection lost) and server message text is dropped.

ssh2 never answers operations issued after the channel closes and buffers unawaited writes without limit, so the capability checks a closed flag before every call, caps open handles at 32 and requests in flight at 64 and 2 MiB (refusing rather than queueing), and closes any handle that arrives after its operation was cancelled. Disposal ends the channel and resolves outstanding operations as closed; the server releases every handle when the channel closes. A remote end of the SFTP channel (EOF with or without close) resolves in-flight operations as connection lost and fails the session (`subsystem-unavailable` before Ready, `network` after). Missing or invalid ssh2 limits fall back to 32 KiB reads and writes and 32 handles.

## Boundaries and rollback

There is no renderer access until SST-020. A FIFO lists as a symlink or `other` and opening it for reading blocks the server's single-threaded SFTP process, stalling every later operation on that session until it is closed; callers must `stat` (which follows links) and open only regular files. Overwrite, temporary files and rename belong to SST-022. A cancelled write may still reach the server. The adapter relies on ssh2 1.17 internals for read/write limits and channel state; an upgrade needs a re-check. Quit and close prompts list terminal sessions only. Rollback removes the session kind, the SFTP adapter and its tests; no data change.
