## Stream ownership

The SSH adapter ([`createTerminal`](../packages/adapters/src/ssh.ts)) is the only owner of ssh2 channel behavior. The shell still opens as `xterm-256color` 80×24 during connect and stays paused until a view opens its stream, so the first prompt bytes are held by ssh2's SSH window rather than lost. After `open`, stdout and stderr chunks are delivered in arrival order as exact-length copies numbered 0, 1, 2… per generation, with empty chunks skipped. Delivery pauses once 256 KiB is unacknowledged and resumes on acknowledgement; there is no main-side queue and no silent drop. Chunks buffered during a credit pause drain per stream; OpenSSH PTY sessions send no extended data, so this ceiling is recorded rather than solved. Input is copied in call order; a backlog over 256 KiB returns `busy` and queues nothing. Resize calls `setWindow(rows, columns, 0, 0)`.

[`SessionRegistry.terminal(owner, id, generation)`](../packages/services/src/sessions.ts) is the single capability fence: it returns the narrowed stream only for the exact owner, session and generation while that attempt is live and `Ready`. Lock, close, failure, owner revocation and reconnect revoke it without terminal-specific code. Reconnect creates a new generation, channel and view; old-generation open/write/resize/ack return `conflict` and nothing is queued across generations, so input is never replayed.

## Remote end versus local close

A remote end is reported only at the stdout/stderr close join, which ssh2 emits after every delivered chunk, so the end always follows the final output. The snapshot then carries `end`: `{kind:'exit', code}`, `{kind:'signal', signal}` (name only; the server's message text is dropped) or `{kind:'eof'}`. The adapter records an exit as soon as it arrives, so a socket loss after the exit still reports it. A socket close after `Ready` without an exit is `Failed`/`network`. Local close/cancel stays `Closed` without `end`. A write racing a remote exit returns `conflict`, never a failure. This fixes the pre-SST-012 behavior where a remote `exit` left the session `Ready` indefinitely (paused ssh2 channels defer `close`, and OpenSSH keeps TCP open). The snapshot `target` now survives teardown so an ended pane still names its execution target.

## Renderer boundary

[Contracts](../packages/contracts/src/terminals.ts) add strict DTOs: owner-scoped `TerminalState` (≤ 32 sessions with phase, target and end), `TerminalOutput` frames (1 B–1 MiB), writes (1 B–64 KiB), integer resize 1–1000 and acknowledgements; a new `busy` error code. The [main controller](../apps/desktop/src/main/terminals.ts) is fence and framing only: handlers authorize the registered main-frame sender and owner, require exactly one validated argument, run synchronously so write order is preserved, and wipe received input bytes. Output frames go only to the owning `webContents`, never through session snapshots. Preload rebuilds DTOs, copies and wipes input and does not filter output by sequence so a gap reaches the view.

The renderer uses `@xterm/xterm` 6.0.0 and `@xterm/addon-fit` 0.11.0 (exact pins, DOM renderer, no CSP change). The declared trust boundary is `xtermOptions` in [`terminal-theme.ts`](../apps/desktop/src/renderer/src/lib/terminal-theme.ts): remote bytes reach the screen only through `term.write(Uint8Array)`; OSC 8 link activation is inert; no clipboard/OSC 52 or web-links addon is loaded; window manipulation reports are off; xterm logging is off. SST-013 enables proposed APIs for Unicode 11 widths and search decorations and adds the explicit Cmd+click link path ([terminal input](terminal-input.md)); remote bytes still enter only through `write`. The [terminal pane](../apps/desktop/src/renderer/src/components/workspace/live-terminal.tsx) acknowledges after xterm's write callback, shows a visible fault on a sequence gap, encodes `onData` as UTF-8 and `onBinary` byte-wise, sends input sequentially and pauses later keystrokes after any refused write until “Resume input”, so the remote only sees a prefix of typed input. Each pane shows the captured label, endpoint, username, explicit PROD and a Signal Blue status with icon and text, and a distinct outcome: exit status, signal, remote close, local close or connection failure. All of an owner's sessions are stacked and stay mounted on other pages so their streams keep flowing. Terminal colors and typography come from the independent terminal theme.

## Boundaries and rollback

There is no renderer connect command; E2E starts sessions from main through the shipped production adapter. A session that no view opens stays paused and its remote exit is not observed until it is viewed. One acknowledgement IPC call per chunk and the fixed 256 KiB bounds are SST-014 inputs. Rollback removes the terminal controller/handlers and renderer pane, restores the paused-channel adapter and drops the xterm pins; there is no schema or user-data change.
