# Session logs, command history and suggestions (SST-034)

Opt-in, local and encrypted. Nothing is sent anywhere; ssterm has no AI feature ([AI scope](ai-scope.md)). Schema stays 4: nothing is written to `catalog.sqlite`.

## Behavior

- **Off by default.** Settings › Recording has two switches. **Record session output** saves what each new terminal displays. **Keep command history** saves each command line a supported shell reports and enables **⌘;** suggestions. Turning a switch on affects sessions started afterwards; turning it off stops that kind of capture in running panes at once and keeps what was already saved.
- **Typed input is never saved.** A password typed at a no-echo prompt (`read -s`, `sudo`, `mysql -p`) does not appear. Anything the terminal *displays* does: echoed input, printed secrets, an echoed snippet body. Output is not redacted.
- **Pane badge.** A captured generation shows **Recording** (blue), **Recording · gaps** (amber), **Recording · partial** (amber, one kind reached its size cap while the other continues) or **Not recording** (amber, with the reason in the tooltip: secure storage unavailable, key unavailable, write failed, size limit). It sits beside, and is independent of, the connection state; both are icon plus text. A pane with nothing captured shows no badge. In a pane under 340 px the badge is icon-only; its accessible name keeps the state.
- **Recordings page** (sidebar) lists session logs newest first with label, PROD/LOCAL, endpoint, start time, size and Recording/Incomplete state; **Export…** and **Delete** per log; **Export history…**, **Delete history** and **Delete all**. Every delete asks first (Cancel focused). The page also shows the copyable shell snippets and the shell matrix below.
- **⌘; at a prompt** (the physical Semicolon key under non-Latin layouts, so Thai Kedmanee works) opens a transient list of up to 8 commands from the same target's history (the saved host, or "local" for This Mac) that start with what is typed, newest first, deduplicated. ↑/↓ select, **Return inserts the rest of the command and never presses Enter**, Esc closes, **⇧⌫ (or the Forget button) forgets** the highlighted command; any other key closes the list without reaching the shell, and every workspace chord is suspended while it is open. Tab, arrows and every Ctrl/Option binding stay with the shell. Insertion re-reads the command line first and inserts nothing if it changed; it goes through the pane's ordered input queue with bracketed paste when the shell asks for it. The list shows a "Reported by the shell; check before running" note.
- **History needs the shell integration** (Recordings page, bash or zsh). ssterm never installs it ([ADR 0005](adr/0005-local-terminal-platforms.md) launch policy unchanged). Without it, ⌘; says so and nothing is recorded as history.
- **What history keeps.** Only command lines reported by `OSC 633;E` from the snippet, parsed in main by a scanner that mirrors xterm.js 6 (7-bit and C1 OSC introducers and terminators, CAN/SUB and other-C1 aborts, payload cap). `decodeCommandLine` is the single gate: it drops a bad escape, invalid UTF-8, more than 2 KiB, blank lines, lines starting with a space, any control character (so multi-line lines), bidi/format controls and credential-shaped lines (best effort: `PASSWORD=`, `--token x`, `mysql -pX`, `curl -u a:b`, `https://u:p@h`, AWS/GitHub/Slack/OpenAI token shapes, JWTs, `Authorization:`, private-key headers). A match drops the line; it is never masked. Commands closer than 200 ms in one session are dropped (replayed logs, forged bursts). The renderer's OSC 133 tracker only locates the prompt; it never supplies recorded content.

## Data and boundaries

| Item | Where | Notes |
|---|---|---|
| Policy | `userData/recordings/policy.json` (0600, atomic) | `{logs, history, logDays 1–365 (30), logMiB 16–10 240 (1024), historyDays 1–365 (180), historyMiB 1–64 (8)}`; missing or invalid means everything off |
| Session log / history | `recordings/out-<uuid>` / `cmd-<uuid>`, `.part` while open or interrupted, `.ssr` once sealed | one file per terminal generation and kind; a reconnect is a new file; never reopened for append |
| Decrypted history cache | main memory, one zero-filled buffer | at most 5 minutes (`MAX_TRANSIENT_MS`); dropped on lock, history delete, disable, forget and quit |
| Per-file key | main memory while the recording is live | zeroed as soon as the final segment is sealed |

The root is created `0700` with a marker file; only allowlisted names are listed, read or removed; links, directories, foreign-owned or multi-link entries are never touched; every unlink and rename is dev/ino-checked (as for `remote-edit-temp`, same-UID mutation between the check and the native call is out of scope). More than 16 384 entries makes the root unsafe: capture fails closed and nothing is deleted. The file header (label, endpoint, environment, start time, scope) is plaintext in the same sensitivity class as catalog metadata so that listing, retention and Delete work without the Keychain.

IPC: six owner-authorized request/response channels (`recordingState`, `configureRecording`, `deleteRecordings`, `exportRecording`, `suggestCommands`, `forgetCommand`); the app lock answers `unauthorized` before the recorder is read. The history scope of suggest/forget is derived in main from the exact live, Ready generation; the renderer never names a scope or a path. Preload re-checks every suggestion (`isCommandText`), so a control or bidi character never reaches the renderer. The badge rides `TerminalSession.recording` on the existing terminal state stream.

## Encryption

- Each file has a random 256-bit data key. It is wrapped by the vault content key with the existing [protection.ts](../packages/adapters/src/protection.ts) v1 envelope under a new binding `{vaultId, recordingId, field: 'recording-key'}`. AAD positions are unchanged, so existing snippet envelopes are byte-identical (golden-vector unit test), and a recording-key envelope never opens as a snippet body or under another recording id.
- Segments use **STREAM** (Hoang–Reyhanitabar–Rogaway–Vizár 2015) in age v1's layout: AES-256-GCM under the file key, nonce = 11-byte big-endian counter ‖ last-flag byte, AAD = SHA-256 of the file's identity block. Frame = u32 length ‖ u8 last ‖ ciphertext ‖ tag. Plaintext = u8 type ‖ body: output (≤ 64 KiB), gap (u64 bytes dropped), command (u64 ms ‖ UTF-8), end (only and always in the last segment).
- Reader verdicts: reordered, dropped or tampered segments, a flipped last flag, a foreign identity or bytes after the last segment are **corrupt**; end of file without a last segment is **incomplete**. The file name is only a hint.
- The vault key never leaves `SecretService` and is zeroed after each call. Each call reads the Keychain once however many items it carries: one read per session start (both files), one per history load, one per export. Frames are sealed from the first byte while the wrap is still in flight, so only ciphertext ever waits; nothing reaches disk until the wrap succeeds.
- Enabling a switch first prepares the vault key (created only when none exists and no ciphertext does, never replaced) and probes it with an empty seal; failure keeps the switch off with the reason.

## Slow disk, failure and size

Capture never blocks the stream and never holds credit or acknowledgements (the SST-014 flow design is unchanged). Output is copied into a 64 KiB buffer and sealed per segment; a 1 s timer seals partial buffers, which bounds what a crash loses. Above 8 MiB of pending ciphertext for one recording (32 MiB for all), output is dropped after sealing what is already buffered, and below 2 MiB an authenticated gap record states how many bytes are missing; the badge turns amber. `ENOSPC`/`EIO` stops the recording with **write failed** (the file stays `.part`, reported incomplete).

A single recording that reaches its kind's size limit stops **only that kind** with **size limit**. Admission reserves space for the full header, encryption/frame overhead, final marker and a possible trailing gap; an oversized incoming chunk keeps only the prefix that fits. The capped file stays `.part`, has no complete end marker, remains exportable and reports **Incomplete**, including after Forget rewrites. The other capture kind can continue with **Recording · partial**, whose tooltip names what is still saved. Retention can evict older closed recordings to fit the configured total budget, but the bounded capped file does not exceed that budget and evict itself. Header writes finish before any encrypted frame is written, including while incoming output or an end event arrives during a slow header write.

## Lifecycle

- Capture is anchored at the session registry: `observeTerminal` runs once per terminal generation at Ready (never for SFTP or tunnels) and sees exactly the frames handed to the view's consumer. Its `end` runs exactly once from a registry-owned resource, which every teardown path disposes — remote end, failure, close, window close/reload/crash (`closeOwner`), lock and quit — after the channel, so no output follows. A throwing observer never breaks the stream or teardown. Frames sent in the short window between an owner revocation and teardown are recorded although no view shows them.
- If a generation ends while its key wrap is still in flight, its ciphertext is written once the wrap succeeds (within the 30 s deadline and the same lock epoch); it is discarded on failure, deadline or a lock.
- Credit-paused bytes discarded by the adapters on failure or lock are absent from the log, exactly as from the view.
- **Lock** (screen lock or suspend, after the registry ended every observer): pending wraps are discarded, the history cache is zero-filled and dropped, and exports before native publication dispatch abort and remove their plaintext stage. An already-dispatched native rename may complete as described below. The renderer drops the suggestion list because the pane leaves Ready.
- **Quit:** session shutdown ends every observer; the recorder revokes in-flight exports/rewrites and drains writers, metadata mutations and retention within one bounded 2 s wait, then zeroes keys. A Forget waiting for the Keychain cannot extend that wait; already-dispatched native IO may finish later.
- **Storage blocked:** the same recorder runs without keys, so local panes show **Not recording** while the policy is on, and Delete still works.
- **Retention** runs at startup, on a policy change, at each recording start and end, and hourly (unref'd timer). Per kind: closed files older than the configured days go first (age is measured from the start time), then the oldest closed files while the kind's total (live files included) exceeds its size limit or there are more than 4 096 files. Live files are never removed by retention.

## Export and delete

- **Export** is the first main-owned `dialog.showSaveDialog`, anchored to the owner window, with a plaintext warning. Its lock epoch starts before the dialog opens, and main reauthorizes the original owner when the dialog returns. A lock during the dialog aborts before reading a decryption key or creating a plaintext stage, even if access is restored before the dialog returns. Main decrypts into an exclusive `0600` stage (`O_CREAT|O_EXCL|O_NOFOLLOW`) next to the chosen path, fsyncs and renames over it. Failure, corruption or a lock before publication removes the stage; the epoch is checked again after fsync/close/identity checks, immediately before dispatching native rename. A native rename already dispatched cannot be cancelled; its acknowledged success reports **saved** even if lock occurs afterwards. Corruption or an unreadable per-file key aborts the whole export, including history, and preserves any existing destination. A log exports as raw output bytes (like `script(1)`; view with `less -R`) with in-band `[ssterm: N bytes not recorded]` and `[ssterm: recording incomplete]` markers. History exports as `ISO-time<TAB>label<TAB>command` lines. A hostile escape sequence in a log replays if the export is `cat`-ed elsewhere. An exported file is outside ssterm's control: retention and Delete do not apply to it.
- **Delete** (one log, all logs, history, all) unlinks the matching files with a dev/ino-checked unlink; a live recording of that kind stops and its file is unlinked once closed, and its badge goes. Bulk deletes also remove recording-named files whose header could not be read. History deletes drop the cache.
- **Forget** (⌘; list) rewrites every closed history file of that target that holds the line under a fresh key (one Keychain read to open them, one to seal the replacements), then unlinks the old file. A live file is excluded from suggestions at once and rewritten at its end. Forget, Delete, retention and final publication share a mutation queue; a pending Forget cannot restore data after a later Delete. Writers whose observer already ended are included; a native create returning after Delete closes/removes its empty file without writing a header or data. Incomplete histories stay incomplete through rewrite. Lock/error cleans unpublished replacements; a refused original unlink reports failure. Across multiple files, earlier rewrites may already have completed when a later file fails; failure never claims the command was forgotten everywhere. Queued Forget actions from a revoked lock epoch do not decrypt. No tombstone keeps the text on disk.
- **Honest residue.** Delete removes the only copy ssterm controls. It does not reach unscrubbed SSD/APFS blocks (ciphertext), OS backups (Time Machine) of the profile and of the Keychain, plaintext exports, or the shell's own history on the host. The vault content key stays, because snippets share it.

## Shell matrix

| Shell | Where | Status |
|---|---|---|
| bash 5.2 | SSH (Debian bookworm fixture) | supported; native unit in the fixture image and E2E through production main |
| zsh 5.9 (macOS `/bin/zsh`) | This Mac | supported; native unit and E2E through the local-terminal seam |
| zsh 5.x | SSH | same snippet, not verified (the fixture image has no zsh and no network to add it) |
| bash 4.4–5.1 | any | same snippet, not verified (Homebrew bash 5 was not installed here; its native test is skipped) |
| bash 3.2 (macOS `/bin/bash`) | any | unsupported: the snippet is a verified no-op |
| fish, sh/dash, ksh, tcsh, nushell, PowerShell | any | unsupported (no snippet) |
| inside tmux or screen | any | unsupported (markers are not forwarded) |

The bash snippet reports through `PS0` and compares `history 1` (no DEBUG trap), so it honours `HISTCONTROL`/`HISTIGNORE`; bash's `cmdhist` saves a multi-line loop as one line, which is then recordable. It adds `__ssterm_status` before and `__ssterm_prompt` after any existing `PROMPT_COMMAND` (newline-separated, so a trailing `;` is harmless) and preserves `$?` for them. Both snippets re-wrap `PS1` with OSC 133;A/B when a prompt theme rebuilt it earlier in the same prompt cycle, so they belong at the end of the startup file; a theme hook registered after the snippet can drop the marks (⌘; then says the integration is missing). Markers are remote-asserted: a remote can forge a command line. Mitigations: a suggestion is inserted only by an explicit ⌘; plus Return, never with Enter, controls and bidi overrides are refused so the shown text is the inserted text, the rate limit and Forget.
